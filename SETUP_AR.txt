إعدادات Night Audit Manager Pro v3

1) استعمل مشروع Supabase الذي جهزت فيه الجداول والسياسات سابقاً.
2) افتح app.js واستبدل PASTE_YOUR_CURRENT_PUBLISHABLE_KEY_HERE بمفتاح sb_publishable الحالي فقط.
   لا تضع sb_secret أو service_role في أي ملف منشور.
3) تأكد أن المستخدم الذي UID الخاص به e2cc0a20-4534-45a5-9135-11c2382134fc موجود في Authentication > Users.
4) يجب أن يكون create_hotel(text) منشوراً كما نفذناه سابقاً، وأن تكون سياسات RLS السابقة فعالة.
5) في Authentication > URL Configuration:
   Site URL: https://houssamosomos.github.io/Night-Audit-Manager/
   Redirect URL: https://houssamosomos.github.io/Night-Audit-Manager/**

حدود هذا الإصدار:
- تسجيل الدخول بالبريد وكلمة المرور.
- عرض المؤسسات المرتبطة بالحساب، إنشاء مؤسسة، تغيير الاسم.
- تسجيل وعرض العمليات المالية المشتركة عبر Supabase.
- المزامنة عند الاتصال بالإنترنت عبر قراءة/كتابة قاعدة البيانات.
- لا توجد بعد واجهة آمنة لدعوة الموظفين. لا تنشئ حسابات الموظفين من المتصفح بمفتاح سري؛ يلزم Supabase Edge Function تستخدم Secret على الخادم وتتحقق من أن المستدعي مدير.
- لا يحتوي هذا الإصدار بعد على كل وظائف v2 (التنبيهات المحلية، مؤشرات الغرف، أرشيف المناوبات والطباعة). هذه واجهة تأسيسية للربط السحابي وليست بديلاً كاملاً عن v2 حتى اختبارها.
- لا يوجد دعم offline-first للمزامنة؛ يتطلب الاتصال بالإنترنت للقراءة والكتابة.

النشر:
ارفع index.html وstyle.css وapp.js إلى جذر مستودع GitHub نفسه، مع استبدال الملفات القديمة. اترك إعداد Pages على main / root.


6) تفعيل نظام Admin وUsers الجديد:
   أ) افتح Supabase > SQL Editor وشغّل الملف:
      supabase/migrations/202611040001_admin_users.sql
   ب) هذا الملف ينشئ app_profiles ويضيف المستخدمين الحاليين كـ user.
      ثم يرقّي حساب المدير الأول المحدد في الملف إلى admin.
      تأكد أن UUID المحدد هو UID حسابك في Authentication > Users قبل تشغيل SQL.
      إذا لم يكن حسابك، استبدل UUID في سطر UPDATE بالـ UID الصحيح.
   ج) انشر Edge Function باسم admin-users:
      supabase functions deploy admin-users
      من مجلد المشروع باستخدام Supabase CLI.
   د) أضف Secret باسم SUPABASE_SECRET_KEY إلى Edge Function secrets،
      وضع فيه sb_secret الخاص بالمشروع (أو استخدم إعدادات Supabase CLI secrets).
      لا تضع هذا المفتاح في GitHub أو app.js أو المتصفح.
   هـ) في Authentication > URL Configuration تأكد من السماح بعنوان:
      https://houssamosomos.github.io/Night-Audit-Manager/
   و) أعد تحميل الموقع. ستظهر لوحة Admin فقط للحساب الذي يحمل role=admin.
   ز) أدخل اسم الموظف وبريده لإرسال دعوة. الموظف يكمل التسجيل ويحدد كلمة مروره من رسالة البريد.

ملاحظات:
- لا يمكن إنشاء حسابات المستخدمين من لوحة Admin قبل تشغيل SQL ونشر Edge Function وإعداد Secret.
- البريد الإلكتروني للدعوات يحتاج إعداد SMTP موثوق في Supabase للإرسال الفعلي، خاصة خارج حدود الرسائل التجريبية.
- هذه النسخة تدير دعوات المستخدمين وتعرض قائمة الحسابات. توزيع المستخدمين على فنادق معينة وتحديد صلاحيات أدق لكل فندق يحتاج خطوة إضافية على hotel_members وسياسات RLS الحالية.
- دور admin في app_profiles لا يمنح تلقائياً صلاحيات تجاوز RLS على جداول الفنادق والمعاملات؛ يجب أن تظل سياسات RLS هي المرجع الأمني.
